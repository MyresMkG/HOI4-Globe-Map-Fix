# HOI4 Globe Map Fix

**1.1.0**：为 Globe Mod 修补地图图标锚点、球背遮挡和地图反向拾取。

（使用gpt-6.1-sol，harness为codex）

## 安装

1. 已安装并启用 hoi4 mod injector：https://github.com/MyresMkG/HOI4-Mod-Injector/releases ；在启动器的播放集中启用 Globe Mod：https://steamcommunity.com/sharedfiles/filedetails/?id=3816496697 。
2. 把成品的 **Globe Map Fix 整个目录**放到游戏的 `injected_mods` 下，最终路径是：

```text
Hearts of Iron IV/
  injected_mods/
    Globe Map Fix/
      Globe Map Fix.dll
      Globe Map Fix.ini
```

3. 重启游戏。此 DLL 通过 LoadLibrary 自行延迟初始化，不需要 injector 调用自定义初始化导出。
4. 检查同目录生成的 `Globe Map Fix.log`。成功时包含 `Installed: 5-byte projection CALL + 7-byte world-picker entry`。injector 日志中的 `loaded` 仅表示 DLL 已载入，不能代替此安装成功记录。

成品只交付在工作目录，本次没有安装到实际游戏目录。

## 行为和范围

- 两处挂钩，共改写 12 字节：通用地图图标路径中的 5 字节 CALL，以及地图世界坐标拾取入口的 7 字节。近地址跳板为 RX；安装时同时验证并写入两处，避免只安装其中一项。
- 地形变形所用的 GlobePosition 算法同步到图标的**临时**世界锚点。普通二维 GUI 继续完成大小、对齐、整数取整、叠放和点击区域设置。
- 通用图标入口包含兵牌、聚合兵牌及其他走同一投影路径的地图图标；不是全局拦截所有投影函数调用。
- 普通缩放调用原投影，球面背面及越界锚点置到屏幕外，避免显示和普通 GUI 命中。没有将球面坐标写回省份、单位或持久锚点。
- 球面下使用游戏原有屏幕射线，反解 GlobeWarp，返回原始地图坐标给现有省份查找、悬停和地块下令流程。覆盖起始平面/球面混合、弯曲过渡、完整球面及经度接缝；普通缩放和地图未激活时走原拾取函数。
- 使用游戏原有高度采样函数，对整数高度做双线性插值。通常用球体解析初值和有界求解，接近地平线时从近侧高度外包球搜索。天空、球背、越界、不收敛或不支持的极点折叠返回未命中，不退回错误的平面坐标。
- 球背遮挡继续以 GlobeFacing 的法线判定为准，并把 GUI 锚点连同普通点击范围移出视口；不只是改变透明度。

## 兼容性与拒绝条件

不使用固定函数 RVA、固定相机成员偏移或固定地图宽高。启动时扫描投影 CALL、世界拾取入口及其原生射线和高度函数，核对独立指令特征；各入口必须唯一。相机容器、主相机和投影矩阵的偏移从匹配指令解码；地图激活条件和地形全局指针从 RIP 相对指令解码。眼点和方向仍由投影矩阵恢复，并在拾取时与原生射线眼点校验。地图尺寸从有效 provinces.bmp 头部读取。

已核对本机 HOI4 **1.19.3.0** 的指令，并在地址不同的测试宿主验证定位。相同指令形态的更新版本可以自行定位；编译器改变寄存器/指令形态、函数 ABI 改变或其他原生模组先修改任一入口时，会拒绝两项修补。不能保证所有未来游戏版本都兼容。

只支持与当前 Globe Mod **0.2.0** 一致的球面变换。读取 shader 的数学部分，忽略空白和注释，再检查变换契约；数学变更会拒绝修补，需要重新审阅 CPU 实现。WATER_HEIGHT 则读取有效 constants.fxh；本版只接受 0～25.5，符合已验证的原生 8 位地形高度范围。

默认读取游戏正在使用的 `dlc_load.json`，按启用顺序解析目录式模组，并处理相关 `replace_path` 遮蔽。没有启用球面 shader 时不修补；数学契约不符、地形 shader 不使用 GlobeWarp、模组元数据缺失、压缩包模组或定位不唯一时不修补。这样会牺牲部分模组组合的可用性，避免在无法确认实际资源时错误启用。没有每帧重新扫描磁盘；更改播放集、shader 或配置后应重启。

用户目录依次从 INI 自定义值、`-userdir` 参数、游戏 `userdir.txt`、Windows 实际 Documents 已知文件夹确定。自定义 `user_data_dir` 必须与游戏实际目录一致，不要指向另一播放集的数据目录。带非 ASCII 自定义路径的 INI 请保存为 UTF-16 LE（带 BOM），符合 Win32 INI API 的读取方式。

## 配置与禁用

`Globe Map Fix.ini`：

```ini
[fix]
enabled=1
probe=0
user_data_dir=
```

- `enabled=0`：下次启动时不修补。
- `probe=1`：检查模组和特征，完全不写进程代码。
- injector 的 `probe=1` 生成的 `diplo_action_hook_probe_only.txt` 同样生效。
- 在 DLL 旁放置空文件 `Globe Map Fix.dllnoinject`，可通过已有 injector 禁止加载。
- 删除整个安装目录后重启即可卸载。DLL 为异步回调和跳板存活期被 pin 到进程结束，不支持运行中 FreeLibrary 卸载。

导出 `GlobeMapFix_GetStatus()` 仅用于诊断：0 等待初始化、1 球面未启用/宿主非 hoi4.exe、2 拒绝修补、3 探测完成、4 已安装、5 INI 禁用。

## 构建和测试

MinGW-w64 x64、C++17。使用系统 Windows DLL 和 Universal CRT；libgcc/libstdc++ 静态链接，不需要另外复制 MinGW 运行库。不是一个 dxgi 代理，不替换 injector。

```powershell
.\build.bat
py .\tools\run_tests.py
```

`MINGW_BIN` 可指定编译器 bin 目录，`OUTDIR` 可指定构建输出目录。默认输出到工作区的 `full_releases\Globe Map Fix`。测试目录是源码的 `build`；GPU 测试从本机 Workshop 读取 shader，没有把原 shader 或游戏文件打包到成品。测试脚本内的 EXE/MOD 路径可按安装位置调整。

测试内容包括：25,409 项数值/JSON/特征检查，其中 6,347 次含地形的逆投影验证和地图接缝、相机环绕、初始混合检查；实际 Globe shader 的 D3D11 WARP 对照；四线程调用期间安装；平面投影和拾取 ABI、球背 GUI 范围、菜单保护条件、模块 pin、重复加载、用户目录和资源冲突；以及真实 injector 加载和 probe 模式。射线函数特征遭破坏时，两处挂钩均不安装。13 个隔离加载用例全部通过。

GPU 对照共 221,184 个锚点，涵盖 800～2400 高度、起始过渡、完整球面和三个倾斜方向。最大世界坐标差 0.075684；可见屏幕内最大位置差 **0.106201 像素**（1920×1080）。新增 **15,553 次实际 shader 与拾取的屏幕往返对照**，最大误差 **0.001221 像素**，全部通过。CPU/GPU trig/rsqrt 有舍入差异，不声明位级完全一致。

合成宿主中，球面投影约 140 ns/图标，原投影约 6 ns，普通缩放约 23 ns；与上一版基本相同。新增常规球面拾取约 **1.1 微秒/次**，地平线附近约 **20 微秒/次**。这些是特定相机/地形的基准，不是所有过渡姿态的最坏耗时，也不能代替实际 HOI4 帧率测量。求解次数有界，没有逐帧磁盘扫描、日志、堆分配或全局锁；相机常量按矩阵变化缓存。TLS 每线程首次使用有运行库初始化开销。

## 已知验证范围

完整报告在成品 `验证报告.json`，绑定实际交付 DLL 的 SHA-256。**尚未执行真实 HOI4 战局画面和鼠标交互测试**，因此不保证绝对无 bug。实际游戏仍需检查聚合兵牌、悬停、地图右键下令、缩放过渡和接缝。

地形拾取按 CPU 高度场求解，没有复制 GPU 的逐帧地形 LOD 三角网格。极陡地形、岸线或恰好在轮廓上的点击可能与 GPU 网格边界不同；近地平线搜索有固定采样上限。通用 GUI 图标的球背已遮挡，独立的 3D 实体射线/特殊 GUI 路径没有额外挂钩。本机已追踪的省份查询均通过已修补世界拾取入口；未验证未来版本的新拾取路径。
